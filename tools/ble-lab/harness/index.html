ble-lab · connection recipe harness

Executes the inferred connection recipe against a real Zwift Click from a plain webpage, and reports pass/fail per step. This is the falsification instrument for docs/virtual-shifting/CONNECTION-RECIPE.md: if a step fails here, the recipe is wrong or Web Bluetooth cannot do it. Close all other software that talks to the Click first.

The ff 04 00 checkbox is the experiment. It is the documented Click-v2 post-handshake vendor write (PROTOCOLS.md §1.5) that our code has never sent, and the leading candidate explanation for the ~45–90 s disconnects. Run it checked and unchecked, watching how long the connection survives each time — that comparison is the whole point, and it also finally gives base validation BV2 a controlled before/after. Set the watch window to at least 180 s so a drop at 90 s is unambiguous.

This browser has no navigator.bluetooth. Web Bluetooth is Chrome/Edge only — Firefox and Safari will never run this page.
